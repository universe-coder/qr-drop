# QR Drop

[English](README.md) · **Русский** · [中文](README.zh.md) · [العربية](README.ar.md) · [Français](README.fr.md)

**Передача файла с одного устройства на другое через поток QR-кодов.** Один экран показывает бесконечную последовательность кодов, второе устройство снимает её камерой и собирает файл. Ни сервера, ни сети, ни сопряжения: только экран и объектив.

**Открыть:** https://universe-coder.github.io/qr-drop/

- После первого открытия работает офлайн (сервис-воркер), файлы никуда не загружаются.
- Отправка работает в любом современном браузере. Для приёма нужны камера и HTTPS.
- Интерфейс на английском, русском, китайском, арабском (справа налево) и французском; светлая и тёмная темы.
- Встроенная самопроверка (`#/selftest`) прогоняет весь конвейер прямо в браузере, кроме камеры.

## Почему это работает без обратного канала

Приёмник не может попросить повторить кадр: сказать это нечем. При этом камера пропускает половину показанного, а то и больше. Нумерованные блоки по кругу здесь не годятся: при устойчивом расхождении частот экрана и камеры одни и те же номера могут пропускаться бесконечно.

Поэтому QR Drop использует **фонтанное кодирование (LT)**: каждый кадр — XOR случайного набора исходных блоков, и приёмнику достаточно любых `K·(1+ε)` кадров, неважно каких. Набор блоков в кадре обе стороны вычисляют из одного лишь номера кадра, так что по каналу не идёт ни байта служебных описаний.

| фаза | кадры | что в кадре |
|---|---|---|
| систематическая | `seq mod 5K < K` | ровно один исходный блок |
| фонтанная | остальные | XOR по robust soliton с лестницей остатка |

Систематический пролог даёт идеальный случай: **при чистом приёме файл собирается ровно за K кадров**, без накладных расходов. Пролог повторяется каждые `5K` кадров для тех, кто навёл камеру позже начала.

### Измеренные накладные расходы

Кадров данных на один исходный блок, симуляция BP-декодера, 60 прогонов на точку:

| K | 0% потерь | 30% | 50% | 60% | 75% |
|---|---|---|---|---|---|
| 137 | 1.00 | 1.23 | 1.28 | 1.33 | 1.39 |
| 1024 | 1.00 | 1.21 | 1.19 | 1.21 | 1.30 |

## Формат кадра

Little-endian. Общие 5 байт: магия `QD`, версия+тип, идентификатор сессии.

**DATA**: 13 байт служебных плюс полезная нагрузка.

```
0  'Q' 'D'                    2
2  (version << 4) | type      1
3  session                    2
5  frame number               4
9  payload                    blockSize
.. CRC-32C                    4
```

**META**: 59 байт плюс имя и MIME: размер файла, размер блока, число блоков, SHA-256 файла, отпечаток расписания, имя, MIME.

Служебные слоты: `0, 4, 8 … 28`, дальше каждый 16-й. Тот, кто навёл камеру сразу, получает описание файла с вероятностью ~98% в первых 32 слотах даже при 60% потерь; в устойчивом режиме служебные кадры занимают 1/16 потока.

- **CRC-32C, а не CRC-16.** Фонтанный декодер подмешивает кадр сразу в несколько блоков, поэтому один незамеченный битый кадр тихо портит весь файл, и узнать об этом можно только по SHA-256 — через минуты съёмки.
- **Отпечаток расписания в META.** Обе стороны работают на одном и том же коде, но одна вкладка может открыть старую сборку из кэша. Отпечаток превращает «мусор вместо файла через три минуты» в честную ошибку сразу.
- **Сырой байтовый режим QR, без base45/base64.** jsQR отдаёт точные `binaryData`; проверено на 700 байтах с нулями и байтами старше `0x7F`.

## Профили

| Профиль | версия QR | коррекция | модулей | байт в кадре | кадров/с | 100 КБ, реально |
|---|---|---|---|---|---|---|
| Надёжно | 13 | M | 69×69 | 316 | 8 | ~95 с (1,1 КБ/с) |
| Обычно | 19 | L | 93×93 | 776 | 10 | ~38 с (2,7 КБ/с) |
| Быстро | 25 | L | 117×117 | 1260 | 12 | ~25 с (4,0 КБ/с) |

Больше данных в кадре — мельче модули и выше требования к камере, свету и устойчивости рук. Оценка «реально» закладывает, что камера распознаёт 35–55% показанных кадров, плюс фонтанные накладные расходы. Предел размера файла — 2 МБ: это уже около полутора часов съёмки.

## Архитектура

```
src/
  protocol/     чистое ядро без DOM, тестируется целиком
    crc32.ts        CRC-32C
    prng.ts         splitmix32 + выбор различных индексов
    soliton.ts      robust soliton distribution
    schedule.ts     ★ единственное место, где кодер и декодер обязаны совпасть
    frames.ts       сериализация кадров
    encoder.ts      файл → бесконечный поток кадров
    decoder.ts      инкрементальный LT-декодер (peeling)
    receiver.ts     сессия приёма: META, чужие сессии, целостность
  qr/
    capacity.ts     таблица ёмкостей, подбор размера блока
    encode.ts       байты → матрица модулей
    paint.ts        матрица → canvas
    broadcast.worker.ts  генерация кадров вне главного потока
    scan.worker.ts       распознавание и разбор вне главного потока
  platform/       камера, удержание экрана, сохранение, вибрация
  app/            хуки и состояние
  ui/             экраны, i18n, небольшой набор компонентов
    locales/        словарь на каждый язык, все типизированы по ru.ts
```

- **Отправка.** Кадры генерируются в воркере с запасом на 12 вперёд. Показ идёт по счётчику тиков `requestAnimationFrame`, а не по часам: кадр обязан жить целое число обновлений экрана, иначе смена рано или поздно попадёт внутрь обновления, и камера снимет половину старого кадра с половиной нового.
- **Приём.** Распознаётся только центральный квадрат под прицелом, уменьшенный до 512×512: втрое дешевле, и заодно отсекаются чужие QR-коды по краям. Следующий снимок не запрашивается, пока не разобран предыдущий.

## Разработка

```bash
npm install
npm run dev       # http://localhost:5173
npm run check     # типы + линтер + тесты
npm run build     # статический сайт в dist/
```

Камера работает только по HTTPS или на `localhost`. Чтобы проверить приём на телефоне, отдайте дев-сборку по HTTPS (например, через туннель) или используйте опубликованный сайт.

`npm run check` прогоняет набор тестов, среди них: петлевая передача с потерей 20/50/70% кадров, приём с середины потока, двоичный round-trip через настоящие QR-коды, растеризованные в пиксели и прочитанные обратно jsQR, и проверка, что порча любого байта кадра ловится CRC.

## Публикация

Сайт полностью статический и использует относительные пути, поэтому `dist/` можно отдавать с любого хостинга и с любого подпути.

GitHub Pages настроен в [`.github/workflows/pages.yml`](.github/workflows/pages.yml): каждый пуш в `main` запускает проверки, собирает и публикует сайт. Однократная настройка: **Settings → Pages → Build and deployment → Source: GitHub Actions**.

## Известные компромиссы

- **jsQR, а не zxing-wasm.** zxing-wasm примерно вдвое быстрее, но тянет WASM-файл, который по умолчанию грузится с CDN. Для приложения, весь смысл которого в работе без сети, это плохой обмен.
- **Отправитель не видит прогресс приёмника.** Канал односторонний, и притворяться иначе было бы нечестно. Экран отправки показывает своё время и номер прохода и прямо говорит смотреть прогресс на втором устройстве.
- **Нативный `BarcodeDetector` не используется.** Он отдаёт только `rawValue` — строку, а не байты.
